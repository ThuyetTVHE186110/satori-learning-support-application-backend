## Appendix: Resolved Decisions

> All previously open items have been confirmed by source code analysis.

| # | Question | Resolution |
|:---|:---|:---|
| 1 | When both Azure STT and SpeechSuper fail, is the message still saved? | **Yes.** Pronunciation runs async fire-and-forget. The user message and AI reply are always saved regardless of pronunciation outcome. |
| 2 | Is SpeechSuper called synchronously or asynchronously? | **Asynchronously**, via `TransactionSynchronizationManager.afterCommit()` + `CompletableFuture`. Never blocks the HTTP response. |
| 3 | Is an empty Azure STT transcript treated as failure or forwarded as empty string? | The client is expected to send `content=""` — the service detects `content.isBlank()` and returns **400 CONTENT_REQUIRED** before any AI call. |
| 4 | When `evaluateSession()` throws, what is the resulting session state? | **Session stays ACTIVE.** `evaluateSession()` is called at line 538 *before* `setStatus(COMPLETED)` at line 571, so a failure rolls back the entire transaction. |
| 5 | Does free-talk session use the same state machine as roleplay? | **Yes.** ACTIVE → COMPLETED / ABANDONED — identical transitions, verified by SM_011–SM_014. |
| 6 | Is there auto-complete logic when the 50-message limit is reached? | **No.** Session remains ACTIVE and blocks further messages with 400. |
| 7 | Is there an idempotency guard on `generate-context`? | **No.** Two concurrent calls both invoke the AI service. The second write overwrites the first. Dev should add a distributed lock if idempotency is required. |
